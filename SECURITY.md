# Security Policy

## Reporting a vulnerability

Do not open a public GitHub issue for a suspected security vulnerability.

If GitHub private vulnerability reporting is enabled for this repository, use
the **Security** tab to submit a private report. Otherwise, contact your
established Finegrained support or design-partner contact and mark the message
as **Security report**.

Please include:

- the affected release version and operating system;
- a clear description of the issue and its potential impact;
- safe, reproducible steps or a minimal proof of concept; and
- any suggested mitigation.

Do not include device tokens, raw Claude Code or Codex traces, credentials,
unredacted local files, or customer data in a report.

## Supported releases

The current public-release channel is pre-release software for authorized
design partners. Security fixes are published in a new release; users should
install the newest available version after being notified by Finegrained.

## Coordinated disclosure

Please give Finegrained an opportunity to investigate and address a report
before disclosing it publicly. We will acknowledge reports through the channel
used to submit them and coordinate a fix or mitigation with the reporter.
